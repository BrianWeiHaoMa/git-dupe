Plain git is not guarded: git-dupe never sees it. To plain git, a private
file is a file the project ignores, and it does to private files what it does
to any ignored file:

  git clean -x        deletes them; git dupe clean spares them
  git stash -a        stashes them, and removes them from disk
  git add -f          stages them in the project, which then tracks them
  a pull or checkout  overwrites one where it brings a file there

A pull or checkout that brings a file of the project's to a path the private
repository tracks overwrites the private file without a word, whether or not
the project's .gitignore names the path. Both repositories then track the
path, and every git dupe command warns of it until one of them stops tracking
it. Checking out a branch without the file deletes it again.

What comes back is what the private repository holds: run from the root, git
dupe restore . brings back every privately tracked file as last staged, the
committed content or, where an edit was staged, the staged one. An edit never
staged is gone. git dupe status shows what differs. Commit private work
before a public pull or checkout, and before git clean -x.

Under git dupe, Git's own messages are printed as Git wrote them, and some of
them name a plain git command to run next: git add and git rebase --continue
after a rebase stops, git push --set-upstream after a push from a branch with
no upstream, git config pull.rebase false after a pull that finds divergent
branches. Typed as written, such a command acts on the project's repository.
git-dupe follows Git's output with a hint that names the git dupe form, such
as git dupe rebase --continue, git dupe push -u origin HEAD, or git dupe
config pull.rebase false, after each of the following; Git's output and exit
status are unchanged:

  a rebase or am that ends with one stopped
  a pull whose rebase stops with nothing unmerged, at an edit for one
  a merge, rebase, or pull whose autostash comes back with conflicts
  a cherry-pick or revert without -n that fails, leaving one stopped
  a commit that exits 1 while a cherry-pick is stopped
  a commit --amend without --allow-empty that exits 1, as empty ones do
  a checkout or switch without --detach or -q that detaches HEAD
  a branch -d, in any spelling, that exits 1
  a failed push that names no remote while the configuration chooses none
  a push or pull on a branch with no upstream, even one with no commit
  a push to an upstream of another name than the branch's
  a push or pull from a detached HEAD
  a push that exits 1, as a rejected one does
  a pull that cannot reconcile divergent branches
  a pull told to fast-forward only that refuses
  an add of a path the private repository ignores

A push or pull on such a branch, or a push to an upstream of another name,
gets its hint where Git refuses it given no refspec and either no remote or
the branch's own: its branch.<name>.remote, or, for a push where that is
unset, the only remote configured, else origin. One from a detached HEAD gets
its hint where it fails given no refspec. A pull gets either only where it
exits 1: given a URL or a path, it merges the remote's HEAD, and where it
cannot, it exits 128.

While a rebase stands stopped, a cherry-pick or revert gets no hint, and a
commit that exits 1 while a cherry-pick is stopped gets the rebase's, as
where the rebase stopped at a pick that became empty. A stopped am is no
rebase: beside one, each gets its hint as anywhere else.
