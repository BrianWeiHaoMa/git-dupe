Keep your own files of a project under a history of their own, out of the
project's repository, and bring them to a second machine. In a clone of the
project where notes/ holds notes of yours and AGENTS.md your instructions for
a coding agent, neither of them the project's, run from the root:

    $ git dupe init
    $ git dupe add notes/ AGENTS.md
    $ git dupe commit -m "Notes and agent instructions"

git dupe init attaches an empty private repository, .git/dupe in this main
worktree, on the branch the project is on. git dupe add notes/ AGENTS.md hides
the directory notes from the project's Git, by a line in .gitdupe, and stages
the files in it; AGENTS.md it stages as a file, hidden by being tracked. A
file the project's .gitignore ignores is added only with -f, as git add adds
one. The commit is private: git status lists none of these files, git log
shows no private commit, and the project's repository never holds them.

Then make an empty repository of your own for the private history, on a host
or a disk you trust, with the project's branch as its default branch:
git dupe clone checks that branch out on the second machine, and refuses,
naming -b, while the default names a branch the repository lacks. On a disk,
git init --bare -b BRANCH makes one, BRANCH being the project's branch. <url>
below stands for its URL; git-dupe refuses a URL of the project's own
repository. Push to it:

    $ git dupe remote add origin <url>
    $ git dupe push -u origin HEAD

HEAD is the branch you are on, the project's branch, which git dupe init took.

On a second machine, clone the project as usual, and from its root run:

    $ git dupe clone <url>

The files committed privately on the first machine appear where they stood
there, .gitdupe among them, so that the same paths are hidden. A file already
in place is kept as it is, and named in a warning when it differs. From then
on, git dupe pull and git dupe push move private work between the two.
