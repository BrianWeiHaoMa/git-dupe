usage: git dupe init [-b BRANCH | --initial-branch=BRANCH]

Attaches a private repository to this worktree, each worktree on its own: an
empty Git repository named dupe in the worktree's own Git directory, at
.git/dupe in the main worktree and at .git/worktrees/<name>/dupe in a linked
one, whose working tree is the worktree's. Git prints its own line for it.
The working tree is recorded relative to the private repository: the main
worktree stays attached when the project is moved, and after "git worktree
move" init run in the linked worktree records its new place for plain Git.

The initial branch is BRANCH, else the branch the project's HEAD names,
else Git's own default. user.name and user.email are copied from the
project's local configuration where they are set there, and the private
repository gets status.showUntrackedFiles=no and advice.statusHints=false.
Nothing is made private.

Unlike "git init", it takes no directory and no other option, and run
again it does not reinitialize: it completes whatever an interrupted init
left undone, changes nothing else, and says so in a hint.

It is refused in a submodule checkout, where a main worktree's .git is not
a directory, in a linked worktree "git worktree add" did not make, and in a
project that tracks .gitdupe.
