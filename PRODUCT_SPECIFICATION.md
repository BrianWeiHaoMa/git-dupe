# git-dupe — Product Specification

## Authority

This document outranks every other document, decision, and line of code in this project. `TECHNICAL_SPECIFICATION.md` is written from it and ranks second. `Fixed decisions` and `Non-goals` hold everywhere. `Guarantees` hold for every use inside `Operating envelope` and bind exactly as strongly there; outside the envelope nothing is promised. What this document leaves undecided is open to `TECHNICAL_SPECIFICATION.md` and to the code, each at its own level; `Left open` names what it hands down explicitly. A line found unworkable is not worked around, narrowed, or made to pass by changing the envelope: the conflict and a proposed amendment are reported, and the line is amended before the code changes, as `CONTRIBUTING.md` says. Labels (`E1`, `F1`, `G1`, `N1`, `L1`) are permanent and are how `TECHNICAL_SPECIFICATION.md`, the code, the checks, and every other document cite this one.

## Product

git-dupe keeps a developer's private files under version control inside a project shared through Git, without those files ever entering the project's repository. The private files — `.env.local`, editor settings, notes, plans, scratch scripts — stay where their tools expect them in the working tree. Their history lives in a **private repository**: a second, ordinary Git repository at `.git/dupe` inside the project's own `.git` directory, whose working tree is the project's. Public work is `git …`; private work is `git dupe …` with Git's own commands, options, output, and exit codes, because git-dupe runs Git against the private repository. Its users are the developer at a terminal, a coding agent acting for them from a non-interactive shell, and scripts, in projects up to the size of a large monorepo.

git-dupe adds little of its own. It attaches and removes the private repository. It keeps the list of **hidden paths** — the paths the developer made private — and keeps public Git ignoring them through rules it maintains in `.git/info/exclude`, so that `git status`, `git add -A`, and a public commit never see them. It gives three commands the meaning a shared working tree needs: `status` and `add` act on the hidden paths instead of on every file of the project, and `clean` cleans the project while sparing them. It refuses the few forms that would stash the whole project or send private history to the project's remote, and it reads the options of `status`, `add`, and `clean` against a fixed table, so that they behave the same under every supported Git. Everything else is Git, unchanged, against the private repository, and `git dupe git …` is that unchanged Git even for the guarded commands.

Terms used throughout. The **workspace** is the project's working tree with git-dupe attached, and the **root** its top-level directory; the **public repository** is the project's repository at `.git`. A path is **publicly tracked** when it is in the public repository's index and **privately tracked** when it is in the private repository's index. The **hidden paths** are `.gitdupe`, every path listed in `.gitdupe`, or, while `.gitdupe` is missing from the working tree and staged without a conflict, in its staged version, and every privately tracked file; a hidden path is hidden whatever stands at it — a file, a directory with everything below it, or nothing yet. The **managed region** is the part of `.git/info/exclude` that git-dupe writes. A **guarded command** is one whose words git-dupe reads before Git runs: `status`, `add`, `clean`, `stash`, `push`, `pull`, `fetch`, and `remote`; the first three have a **table**, the option spellings git-dupe reads for them.

**What must not go wrong, and the accepted limits.** git-dupe, of its own accord, never writes private content into the public repository's objects, index, refs, or configuration, and never sends private history to a destination that names the project's repository or a remote of it (G18), unless the developer asks for exactly that through `git dupe git`; the guard compares names, so a destination Git rewrites through `url.<base>.insteadOf`, a local path beginning with `~<user>`, which Git reads from that user's entry in the password database, and a remote that a file in either repository's `remotes` or `branches` directory defines instead of its configuration, are not seen through. When a git-dupe command that G6 covers ends, every hidden path is ignored by public Git, or the command has named the path that is not and the rule that exposes it when a rule does. The commands git-dupe adds or changes, other than `git dupe git`, never delete or overwrite a file in the working tree other than `.gitdupe`, except what the user's own `clean` deletes among the paths that are not hidden. Beyond that, git-dupe promises what Git promises: an interrupted command leaves what Git leaves, and recovery is `git dupe` against private history. Four limits are accepted. Plain `git` is not guarded: `git clean -x`, `git stash -a`, `git add -f`, and a public checkout that writes onto a hidden path do to private files what Git does to any ignored file; staged or committed private content comes back from the private repository, and edits never staged do not. A file the project ignores that is not yet privately tracked on this machine is overwritten, silently and as Git does it, when a private `pull`, `switch`, `checkout`, `merge`, or `rebase` brings a file at its path from another machine; `git dupe clone` keeps such files, and Git's own `switch`, and `checkout` of a branch, refuse to overwrite them under `--no-overwrite-ignore`. The managed region applies in every worktree of the project, because `.git/info/exclude` is shared by all of them, while private versioning exists in the main worktree only. A `!` rule in a `.gitignore` that the public repository tracks and a sparse checkout keeps out of the working tree is not seen (G6).

**Scale.** One developer or agent per clone at a time; one private repository per workspace; up to a few thousand privately tracked files under at most a thousand hidden paths not below another hidden path (E8), inside public repositories up to the size of a large monorepo.

## In use

1. In a clone of the project, on its branch `main`, the developer runs `git dupe init`. Git reports the new repository under `.git/dupe`; `git dupe status` shows branch `main` with nothing to commit and a `hint:` that nothing is private yet and that `git dupe add <path>` makes a path private.
2. They run `git dupe add notes/`. git-dupe lists `notes` in `.gitdupe`, prints a `hint:` that `notes` is now hidden from the project's Git, naming `git dupe unhide`, and Git stages the files under it and `.gitdupe`. `git dupe add .env.local` is refused by Git as any ignored file is, with Git's hint to use `-f`; `git dupe add -f .env.local .vscode/` stages both and hides `.vscode`. `git dupe add docs/notes.md` stages that file, hidden by being privately tracked, while `docs/design.md` beside it stays visible to public Git. `git dupe commit -m "Local settings"` commits them with `.gitdupe`. Public `git status` lists none of these, `git add -A` stages nothing private, `git log` shows no private commit, and a fresh `git clone` of the project holds none of them.
3. Daily, they edit `.env.local` and write `notes/today.md` and `.vscode/launch.json`. `git dupe status` shows `.env.local` modified, `notes/today.md` untracked, and `.vscode/launch.json` among the ignored files; public `git status` shows none of them. `git dupe add -A` from any directory, or `git dupe add .` from the root, stages every change under the hidden paths and nothing else, and `git dupe add .` from inside `notes/` stages what is under `notes/`; `git dupe add -f .vscode/launch.json` adds the ignored one; `git dupe add -p` stages part of a change. `git dupe commit`, `diff`, `log -p`, `blame`, `restore`, `stash`, `switch -c experiment`, and `merge experiment` are Git's, and a branch switch in one repository never moves the other. A new `src/scratch.py` appears in public `git status` and not in `git dupe status` until they decide: `git add` makes it public, `git dupe add src/scratch.py` makes it private. `git dupe rm --cached src/scratch.py` releases it, and git-dupe warns that public Git can now see it. `git dupe unhide notes/` stops hiding the directory while its privately tracked files stay hidden; `git dupe hide scratch/` hides a path before anything is added there; `.gitdupe` can also be edited by hand, one path per line.
4. To reset the tree they run `git dupe clean -fdx`: build products and every other untracked file are deleted; the hidden paths stay. When plain `git clean -fdx` is typed from habit, private files go with the rest; `git dupe status` then shows them deleted, and `git dupe restore .` from the root brings back every privately tracked file as last staged; edits never staged are gone.
5. `git dupe remote add origin git@host:me/project-private.git` (the project's own remote URL is refused), then `git dupe push -u origin main`. On another machine they `git clone` the project and run `git dupe clone git@host:me/project-private.git`: `.gitdupe` and the missing private files appear, an `.env.local` already there is kept, named in a warning when it differs, and shown as modified, to keep with `git dupe commit -am` or replace with `git dupe restore .env.local`. From then on `git dupe pull` and `git dupe push` move private work between machines.
6. A coding agent drives it from a non-interactive shell: `git dupe status --porcelain` lists changes and `??` and `!!` entries under the hidden paths and the paths whose deletion is staged, and nowhere else but an ignored directory that holds a hidden path and no privately tracked file, which Git reports as one `!!` entry; `git dupe add . && git dupe commit -m "Plan"`; `git dupe clean -fdx` between runs. A refusal is one `fatal:` line on standard error, exit 128, naming the command to use instead when there is one; a usage error exits 129; a warning is a `warning:` line that changes no exit status. git-dupe adds no prompts; Git's own prompts are avoided as for Git, with `-m`, `GIT_EDITOR`, and `GIT_TERMINAL_PROMPT`.
7. A script tests for `.git/dupe` to learn whether a workspace is attached, reads `.gitdupe` and `git -C "$root" dupe ls-files -z` for the hidden paths, and reads exit codes as Git's. A tool that cannot call `git dupe` reads the private repository with `git --git-dir="$root/.git/dupe" log`.
8. `git dupe git add -i`, `git dupe git status --porcelain=v2 --newoption`, or any `git dupe git <words>` runs Git against the private repository with the words as typed, guarded by nothing: the route to an option a table does not hold, and to a refused form the developer means.
9. `git dupe detach` removes the private repository and the managed region, leaves every file on disk, and refuses without `--force` while private work is uncommitted or on no remote.
10. `git dupe help`, `git dupe help add`, `git dupe -h`, and `git dupe add -h` describe git-dupe's own commands, a screen each; `git dupe log -h` shows Git's usage for `log`; `git dupe --help` opens the manual page. Git's global options go before `dupe`: `git -C project dupe status`, `git --no-pager dupe log`, `git -c color.ui=never dupe status`.

The most common failure is an option that a table does not hold, typed from habit or mistyped: `git dupe add --pathspec-from-file=list`, `git dupe status --porcelian`. git-dupe runs nothing, prints one `error:` line naming the word and `git dupe git` as the unguarded route, then the command's usage line, and exits 129.

## Non-goals

- **N1.** No encryption, secret detection, or access control: the private remote is the trust boundary, and git-dupe reads and writes private files as plain files.
- **N2.** No files outside the workspace. A dotfile manager is a different product.
- **N3.** No interception of plain Git: no hook in the public repository, no wrapper around `git`, no daemon or file watcher, no git-dupe variant of public `git add`. What is typed to plain `git` is not guarded.
- **N4.** No transaction, journal, backup, undo, or rollback layer of its own. Git's index, refs, reflog, and in-progress state are the only recovery state.
- **N5.** No reimplementation of Git: no own diff, merge, index, ignore matching, glob or pathspec matching, transport, or status rendering. Comparing one literal path with another is not matching.
- **N6.** No configuration file or environment variable of git-dupe's own, no file of its own other than `.gitdupe`, and no command-line option of its own beyond `-h`, `--version`, and the options its own commands define (G1, G2, G3). Git's configuration and Git's global options decide color, paging, locale, and verbosity, as they do for Git.
- **N7.** No ignore file of its own: `.gitdupe` holds paths, never patterns. `.gitignore`, the global excludes, and the private repository's `.git/dupe/info/exclude` are the ignore rules for private work, exactly as for any Git repository.
- **N8.** No pre-check of a private `checkout`, `switch`, `restore`, `reset`, `merge`, `rebase`, `pull`, `cherry-pick`, `stash pop`, or plumbing command for collisions with files the private repository does not track. Git's own rules for untracked and ignored files apply unchanged.
- **N9.** No private version of a publicly tracked file on purpose: a path is tracked by one repository or the other.
- **N10.** No platform other than Linux, and no linked worktree, submodule checkout, or bare repository as the workspace.
- **N11.** No reading of the option grammar of `status`, `add`, and `clean` beyond their tables: no abbreviated long option, no option a later Git adds, no `--pathspec-from-file`, and no interactive `add -i` under a guard. `git dupe git` is the route to them.
- **N12.** No second private repository per workspace, no GUI, editor integration, shell completion, or telemetry.

## Operating envelope

Behavior outside the assumptions below is not promised.

- **E1.** The machine runs Linux, and the workspace lives on a local, case-sensitive filesystem, with `core.ignoreCase` false in both repositories, as Git leaves it there.
- **E2.** One person or agent works in a workspace at a time, and git-dupe commands do not overlap each other or a public Git command that writes to the working tree. Between git-dupe commands they run any public Git command and edit any file, `.gitignore` and `.gitdupe` included. While a git-dupe command runs, no other process changes the working tree, either repository, or `.git/info/exclude`.
- **E3.** They do not hand-edit the managed region or its markers, and they change the private repository's index and refs only through `git dupe`; plain Git is used against `.git/dupe` to read it and to clone, fetch, or push from it, and its `config`, `hooks`, and `info/exclude` are edited as in any repository. A template directory that Git's `init` copies into `.git/dupe` for `git dupe init` or `git dupe clone` holds no symbolic link, no file `commondir`, and no `config` that gives `extensions.refStorage` a location.
- **E4.** Private files are regular files and symbolic links inside the workspace, and neither a path inside the workspace nor the path of any working tree or Git directory of the project holds a newline.
- **E5.** The `git` on `PATH` is a supported version (F4). The private remote is a destination the user chose for private content, reached through Git's own transports and credentials.
- **E6.** A command may be interrupted or killed at any point and run again.
- **E7.** The filesystem accepts every write git-dupe makes under `.git` and to `.gitdupe`.
- **E8.** The hidden paths not below another hidden path number at most 1,000, and their paths together take at most 128,000 bytes, the budget from which the managed region and the path lists git-dupe gives Git on one command line are built; git-dupe runs with a stack size limit of at least 8 MiB, Linux's default, and an environment small enough that such a list fits on one command line beside it, as any environment under 1 MiB, counting eight bytes for each variable, is.

## Fixed decisions

- **F1.** git-dupe is written in Rust and built with the Rust 1.98.0 toolchain, which the repository pins. It ships as one executable named `git-dupe`, invoked as `git dupe`, and runs on Linux.
- **F2.** Git performs all versioning. The private repository is an ordinary Git repository whose Git directory is `.git/dupe`, inside the public repository's `.git` directory, and whose working tree is the root, located relative to that Git directory so that moving or renaming the workspace keeps it attached. Plain Git can read it, and clone, fetch, or push from it. Its local configuration, as `init` and `clone` leave it, carries `status.showUntrackedFiles=no`, so that Git's own status of it, and the status in its commit-message template, do not enumerate the project's files unless asked to (`git dupe status` asks for untracked files itself, G12), and `advice.statusHints=false`, so that no status hint names a plain `git` command for a private file. Its hooks, configuration, and `info/exclude` are its own, as in any repository: the public project's hooks and local settings do not apply to private work.
- **F3.** Public Git ignores hidden paths through `.git/info/exclude`, in the region between the lines `# BEGIN git-dupe` and `# END git-dupe`. The region holds one rule per hidden path not below another hidden path, each anchored to the root and matching exactly that path whatever characters it holds, and nothing else; the rest of the file is the user's and is preserved. Nothing versioned is added to the public project.
- **F4.** git-dupe supports every Git release at or above 2.43.0 and below 3.0.0, and `git dupe help` names that range. The repository lists the minor releases it checks — 2.43.0, 2.44.0, and so on through the newest, 2.56.0 at this writing, and the list is raised as new minor releases appear — and its checks run every scenario under each of them, obtained once from its official source release and built into a directory under the repository root that Git ignores, reused when present; the Git on `PATH` is not a check target. A table holds only options that exist with the same value form in every listed release and mean the same in each, apart from the differences between releases that `TECHNICAL_SPECIFICATION.md` records.
- **F5.** `.gitdupe` is a file at the root, one path per line, relative to the root: a leading `/` and a trailing `/` are tolerated and dropped, an empty line is skipped, and every other line is a literal path, never a pattern or a comment; a line that, cleaned as G11 cleans an operand, names the root or a path outside it hides nothing and is named in a `warning:` on every command G6 covers until it is removed. `hide`, `unhide`, and `add` write it and stage it when they hide or unhide a path (Git's `add` leaves an entry it assumes unchanged as staged, `.gitdupe`'s included), and refuse to, exit 128, changing nothing and naming `git rm --cached .gitdupe`, while it is publicly tracked and not privately tracked; the developer may edit it; it is committed, cloned, and merged like any privately tracked file; the managed region always hides it.
- **F6.** git-dupe adds seven commands — `init`, `clone`, `detach`, `hide`, `unhide`, `git`, `help` — and gives three their shared-working-tree meaning: `status`, `add`, `clean`; Git's `stage`, its builtin synonym for `add`, is read as the word `add` wherever git-dupe reads a command word, so that it is `add` under `git dupe` and Git's own `stage` under `git dupe git`. It guards the untracked forms of `stash` (G17) and the destinations of `push`, `pull`, `fetch`, `remote`, and `clone` (G18). Every other Git command, and every option a guard does not refuse, runs against the private repository unchanged.
- **F7.** git-dupe takes no options of its own before the subcommand other than `-h` and `--version`. Git's global options — `-C`, `-c`, `--no-pager`, `-p`, `--literal-pathspecs`, and the rest — are given before `dupe`, where they reach every Git process git-dupe runs as G19 describes; given after `dupe` they are a usage error naming the `git <options> dupe` form.
- **F8.** git-dupe's own lines use Git's `level: message` form with no program-name prefix — `fatal:` for a refusal, `error:` for a usage error, `warning:`, `hint:` — go to standard error, are not colored, and are English whatever Git's locale. Git's own lines follow Git's locale and color settings.
- **F9.** Exit codes are Git's: a command passed to Git returns Git's status unchanged; a refusal by git-dupe exits 128; a usage error of git-dupe's own — a misuse of one of its own commands, a dashed word a table does not hold (G26), a Git global option after `dupe`, an alias G19 refuses — exits 129 after its `error:` line and the command's usage line; bare `git dupe` prints usage and exits 1 as bare `git` does; `-h` alone, `-h` or `--help` on a command whose help is git-dupe's (G24), `--version`, and git-dupe's own `help` pages exit 0. A warning or hint never changes an exit status.
- **F10.** A manual page `git-dupe(1)` ships with each release. It says what `git dupe help` and the ten command texts of G24 say, and, being the one text of git-dupe's not bound to a screen, it says more: a quick start from `init` through `add`, `commit`, `remote add`, and `push -u` to a second machine's `clone`, examples of daily use, and the explanations the screen of G24 has no room for. It describes only what the build it ships with does.

## Guarantees

Every guarantee below holds for all use inside the operating envelope.

### Attaching and leaving

- **G1.** `git dupe init [-b BRANCH | --initial-branch=BRANCH]` creates an empty private repository and prints Git's own line for it. The initial branch is `BRANCH`, else the branch the public repository's `HEAD` names, else Git's own default; a template directory of the developer's that itself holds a `HEAD` is copied as plain `git init` copies it, and its `HEAD` stands in place of that branch. It copies `user.name` and `user.email` from the public repository's local configuration into the private repository where they are set there, makes nothing private, and takes no other option. In an attached workspace it completes whatever a killed `init` left undone, changes nothing else in the private repository, says so, and exits 0; a private repository whose working tree is not recorded as `init` records it (F2) is one a killed `init` left undone, however it came to be so, and `init` then sets again the settings F2 and this line name.
- **G2.** `git dupe clone URL [-b BRANCH]` attaches from an existing private repository: it creates the private repository as `init` does, adds `URL` as the remote `origin`, fetches it, and checks out `BRANCH`, else the remote's default branch, as a local branch tracking it. It writes every privately tracked file absent from the working tree and leaves every file or directory already present as it is; one that differs from the checked-out version, in content or in kind, is named in a `warning:` and then shows as an unstaged change; a file present where the checked-out version has a directory is named the same way, and the files below it stay unwritten and show as deleted. A `.gitdupe` already present is kept the same way, and the hidden paths follow it until the developer resolves the difference. Where the private repository is configured for a sparse checkout, as a template directory of the developer's can configure it, a privately tracked path outside its sparse set stays unwritten, as Git leaves it. It takes no other option. It refuses, exit 128, in an attached workspace and when G18 refuses `URL`. When the remote has no branch, the workspace stays attached with `origin` configured and no commit. Any other failure leaves the workspace attached with what was done; `git dupe detach --force` followed by `git dupe clone` starts over.
- **G3.** `git dupe detach [--force]` removes the private repository and the managed region, leaves every file on disk, `.gitdupe` included, and names in a `warning:` each formerly hidden path that public Git can now see. Without `--force` it refuses, exit 128, when Git's status of the private repository reports any change not committed — to a file it tracks, or a staged addition or deletion — when a commit on a private branch, tag, or stash entry is an ancestor of no remote-tracking branch (with no remote configured every commit counts), or when the private repository cannot be read. With or without `--force` it refuses, exit 128, changing nothing, while `.git/info` is a symbolic link and the region stands in the file read through it, naming the link. History removed by `detach --force` is gone; git-dupe keeps no copy.
- **G4.** Every command except `init`, `clone`, `help`, `-h` alone, `-h` or `--help` after a command, `--version`, a usage error of F7 or G26, and bare `git dupe` requires an attached workspace and works from any subdirectory of it; in an unattached repository it exits 128 naming `git dupe init`. Outside any repository, every command other than `help`, `-h` alone, `-h` or `--help` after a command, `--version`, a usage error of F7 or G26, and bare `git dupe` — `init` and `clone` included — exits 128 with Git's own message that this is not a repository. `init` and `clone` attach only the main working tree of an ordinary, non-bare repository whose `.git` entry is a directory; in a bare repository, a linked worktree, or a submodule checkout, and in a project that publicly tracks `.gitdupe`, they are refused with an explanation, exit 128, naming the main working tree when Git reports it.

### Hidden paths

- **G5.** Of its own accord, git-dupe writes inside the public repository's `.git` directory only `.git/dupe`, the managed region, and `.git/info` when it is missing, to hold the region, and inside the working tree only `.gitdupe` and, in `clone`, the files G2 writes; a command passed to Git writes where the developer's words tell Git to. The only public Git command it runs that changes anything is the `git clean` of G16; its other uses of public Git only read.
- **G6.** Every command other than `help`, `-h`, `--version`, a usage error, and `detach`, when it ends in an attached workspace and whatever its exit status (a killed command: G21), leaves the managed region holding exactly the hidden paths as F3 describes, and has asked Git whether public Git ignores each of them; a refusal that this document says changes nothing still does this. Each one public Git does not ignore — a `!` rule in a `.gitignore` re-includes it — is named in a `warning:` with the file and line of the deciding rule when a rule decides, on every command until the rule or the path changes. A `.gitignore` that the public repository tracks and a sparse checkout keeps out of the working tree is not consulted. A hidden path with a symbolic link among its ancestors is one public Git never looks at and Git will not answer for; it is named in a `warning:` instead of being asked about. If `.git/info` is a symbolic link, or `.git/info/exclude` a dangling one, the region is left as it is, the entry and its target untouched, and a `warning:` says the region cannot be maintained there; the command still asks about exposure and keeps its exit status. While the private repository cannot be read — what a killed `init` leaves until it is run again (G21) — the region is left as it is, a `warning:` names `git dupe init`, and the command keeps its exit status.
- **G7.** Once a git-dupe command has ended with a path hidden, a new file under it is ignored by public Git without any further git-dupe command, unless a `!` rule re-includes it or G6 leaves the region as it is, both of which G6 reports, apart from a rule in a `.gitignore` it does not consult. A publicly tracked path under a hidden directory stays tracked and visible to public Git, because ignore rules do not affect tracked paths: a hidden directory hides what public Git does not track.
- **G8.** A path tracked by both repositories — through a plain `git add -f`, or a public checkout or pull that writes a public file onto a privately tracked path — stays hidden and is named in a `warning:` by every command G6 covers until one side releases it.
- **G9.** When a path the managed region hid at a command's start is no longer hidden when the command ends — after `unhide`, an edit of `.gitdupe`, a command that stopped tracking a file privately, or what a killed command left — while something remains on disk at it that public Git does not ignore, the command names the path in a `warning:` as visible to public Git.
- **G10.** Every Git process git-dupe runs against the private repository is given that repository explicitly, with every environment variable that locates a repository, index, or object store — `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, and `GIT_REFERENCE_BACKEND`, which Git reads from 2.54.0 — replaced or cleared whatever the caller's environment holds, so that `git dupe` run from a hook or alias of the public repository acts on the private repository and never on the public index.
- **G11.** `git dupe hide PATH...` adds each path to `.gitdupe` unless it is listed or lies below a listed path, cleaned of `.`, `..`, and repeated or trailing slashes and made relative to the root, whether or not anything stands at it, and prints one `hint:` per newly hidden path naming it and `git dupe unhide`. It refuses, exit 128, changing nothing, a path that is publicly tracked or a directory that holds a publicly tracked path, naming the count and that such paths become private one file at a time after `git rm --cached`. `git dupe unhide PATH...` removes each listed path from `.gitdupe`, prints one `hint:` per path, and leaves a privately tracked file below it hidden. Both take no option; the root itself, a path outside it, and a word holding `*`, `?`, or `[` or beginning with `:` are usage errors.

### status

- **G12.** `git dupe status ARGS` prints Git's own status of the private repository, with every option of the table keeping Git's meaning. Without a pathspec from the user, Git is confined to the hidden paths and the paths whose deletion is staged, and asked for untracked and ignored files, so that the output shows every change Git reports to a file the private repository tracks or has staged for deletion, every untracked file under a hidden path that no ignore rule hides and no directory named `.git` holds, collapsed as Git collapses untracked directories, and, in Git's ignored section, what an ignore rule hides under a hidden path, collapsed as Git collapses ignored directories, which reports an ignored directory that holds a hidden path and no privately tracked file as that one directory; it lists no untracked file outside the hidden paths, except what stands on disk at or below a path whose staged deletion it shows, and no publicly tracked path that the private repository neither tracks, nor has staged for deletion, nor tracks a file below. A `-u` or `--ignored` from the user replaces the mode git-dupe asked for. The diff that `-v` adds is Git's, over the whole index, whatever the confinement. With pathspecs from the user, each a literal path, the output is the same confined status over the hidden paths and the paths whose deletion is staged at or below those paths, and the paths at or below a hidden path; a pathspec holding `*`, `?`, or `[`, or beginning with `:` other than `:/`, which names the root, is a usage error naming `git dupe git status`. When nothing is hidden other than `.gitdupe`, a `hint:` on standard error names `git dupe add`.

### add

- **G13.** `git dupe add ARGS` reads its operands as paths. An operand spelled `.` or `./`, an operand naming the root (`:/`, or its absolute path), and `-A` or `--all` without an operand act on the hidden paths: `-A` and the root on all of them, `.` on those at or below the current directory, or on the current directory itself when it lies below a hidden path; these forms never hide a new path, and when nothing hidden other than `.gitdupe` lies there, `add` runs no `git add`, prints a `hint:` naming `git dupe add <path>`, and exits 0. Every other operand is a literal path taken as given: a directory neither at nor below a hidden path is hidden first, exactly as `git dupe hide` would hide or refuse it, or under `-n`/`--dry-run` only named in the `hint:` as the path that would be hidden; a file is hidden by being privately tracked once Git adds it. An operand holding `*`, `?`, or `[`, or beginning with `:` other than `:/`, is a usage error naming `git dupe git add`. Every word other than these operands is given to Git as written.
- **G14.** `add` never stages a publicly tracked path: named as a file operand, it is refused, exit 128, staging nothing, with the instruction to `git rm --cached` it first; under a directory operand at or below a hidden path, or under the hidden paths, it is left unstaged, a privately tracked file below it may be left unstaged with it, and the count of skipped paths is reported in a `warning:` (a directory not yet hidden that holds one is refused as G11 says). `-f` does not override this. A path already tracked by both (G8) is updated as any privately tracked file.
- **G15.** Otherwise `add` is Git's add against the private repository: `.gitignore`, the global excludes, and `.git/dupe/info/exclude` apply as in any repository, so a file the project ignores is added only with `-f`, and Git's own message and exit status say so when it is not.

### clean

- **G16.** `git dupe clean ARGS` runs `git clean` in the public repository with the user's words, from the user's directory, and never deletes a hidden path, anything below one, whatever stands at one, or an untracked nested repository that holds one — a directory holding a `.git` entry counts as one, whether or not Git would open it — whatever `-x`, `-X`, `-d`, `-i`, `-e`, or a pathspec says. Among the rest it deletes what `git clean` would delete, under public Git's ignore rules and `clean`'s own options and safeguards, with Git's output and exit status, except inside a directory that holds a hidden path and that plain `git clean -X` takes as ignored as a whole, because a rule names it or every other entry in it is ignored: under `-X` that directory's exclusion is lifted for Git and the hidden paths inside it are excluded again, so that with `-d`, from the root and without a pathspec, Git enters it and deletes the ignored files inside it other than what this guarantee spares, where plain `git clean -X` would have deleted the whole directory; in every other form of `-X` — without `-d`, from a directory inside it, or with a pathspec — an ignored file inside it is deleted where Git's own `clean -X` under those rules reaches it and kept where it does not, because the user's directory or pathspecs do not cover it, or because a directory standing at a hidden path, a nested repository, or an ignored directory inside it is again one entry to Git, and a directory whose every entry is one of these or an ignored file is again one entry too, kept whole without `-d`; whether or not plain `git clean -X` would have deleted or kept the whole directory. `-X` given together with `-e` is refused, exit 128, deleting nothing, and so is every form while a hidden path has a symbolic link among its ancestors inside the workspace, naming the path and the link: public Git never looks beyond the link (G6), and its `clean` would delete the link and what it leads to.

### stash

- **G17.** `git dupe stash` in its `push`, `save`, and bare forms is refused, exit 128, when a word before `--` spells `-u`, `--include-untracked`, `-a`, or `--all` as Git would read it — in full, as a prefix, or in a bundle — because in the private repository, where every file of the project is untracked, they would stash, and remove from disk, every untracked file they cover; the refusal names `git dupe add` first, then `git dupe stash`. Every other form of `stash` is Git's.

### remotes

- **G18.** `push`, `pull`, `fetch`, `remote`, and git-dupe's own `clone` refuse, exit 128, sending, fetching, and configuring nothing, when a word after the command or the part of a word after its first `=` names a **public place**, and `push`, `pull`, and `fetch` also when a URL that the private repository's configuration gives any of its remotes names one, the refusal then naming that remote and `git dupe remote remove`; and `push`, `pull`, and `fetch` given no repository also when the one Git takes in its place from `branch.<name>.pushRemote`, `remote.pushDefault`, or `branch.<name>.remote` is a URL or path, `.` included, that names one. A public place is any URL that the public repository's configuration gives any of its remotes, with the same host and path once the scheme, user, port, a `.git` suffix, and trailing slashes are removed and `[user@]host:path` is read as `host` and `/path`, a local path compared by the canonical form of each path Git opens for it — the path, the path with `.git` appended, and each of those with `/.git` appended; or any working tree of the public repository — the root, or a linked worktree as `git worktree list` names it — its `.git` entry, or its Git directory, reached by any absolute path, by a path beginning with `~` or `~/` read from the home directory `HOME` names, or by a relative path read from the root. The refusal names the place and `git dupe git` for a destination the developer means. This is a comparison of names, not a proof that a destination is private.

### Everything else

- **G19.** Every command git-dupe neither adds nor changes — the guarded ones once their guard has passed — runs against the private repository with Git's own arguments, output, colors, pager, editor, hooks, aliases, configuration, prompts, and exit status. Paths are the workspace's paths and revisions are private history. Git's global options given before `dupe` apply to every Git process git-dupe runs, except that `--git-dir` and `--work-tree` name the public repository, and that a pathspec setting — `--literal-pathspecs`, `--glob-pathspecs`, `--noglob-pathspecs`, `--icase-pathspecs` — governs the developer's own pathspecs and not the paths git-dupe adds for `status`, `add`, and `clean`. An alias is read as Git reads it: one whose expansion, after any Git global options at its start, begins with a command git-dupe adds, changes, or guards is treated as that command with the expansion's arguments, those options applying as if given before `dupe`, except that a `--config-env` among them reads its variable in each Git process git-dupe runs, where the variables G10 sets or clears, and those git-dupe removes from its own runs, hold that process's values; a `!` alias runs as Git runs it, unguarded. A word that git-dupe neither adds, changes, nor guards and that supported releases do not all read as the same alias — it also names a command Git runs before consulting aliases, or its alias is configured in a form only some of them read, as `alias.<name>.command`, under an empty subsection, or under a name that holds a dot — is a usage error, exit 129, naming the alias and `git dupe git`, when an expansion of it, read the same way, reaches a command git-dupe adds, changes, or guards, because supported releases differ on what Git runs for it. Git's `help.autocorrect` does not apply under `git dupe`, whatever the configuration or a `-c` before `dupe` sets: a word that names no Git command and no alias is reported with Git's suggestions, exit 1, and never run as another command.
- **G20.** `git dupe git WORDS`, where `WORDS` begin with a Git command or alias, runs Git with `WORDS` against the private repository as G10 and G19 describe, with no guard, no table, and no change to the words, and settles as G6 describes; a Git global option at the start of `WORDS` is the usage error F7 names.
- **G21.** A command killed at any point leaves the private repository and the working tree as Git leaves an interrupted command, and leaves `.git/info/exclude`, and `.gitdupe` where git-dupe itself writes it, each either as it was or as the command would have left it, never partially written; the next command G6 covers brings the managed region up to date. A killed `init` is completed by running it again, once any lock file Git names as left behind in `.git/dupe` is removed, as after any killed Git command, a killed `detach` by `git dupe detach --force`, and a killed `clone` as G2 describes.
- **G22.** A git-dupe command runs Git a number of times that does not depend on how many files either repository holds, never once per file; git-dupe itself never walks the working tree, copies it, or rehashes content. The untracked and ignored walk that `status` asks of Git covers the hidden paths and the paths whose deletion is staged, and outside them reads only the entries of each directory above them; `clean` walks what the user's `git clean` walks and, under `-X`, the directories G16 enters.
- **G23.** git-dupe never gives Git a shortened list of paths: a command whose list for one Git command line — the hidden paths, or the publicly tracked paths under them that `status` leaves out and `add` skips — does not fit on that command line is refused, exit 128, naming their count.
- **G24.** `git dupe help [COMMAND]`, `git dupe -h`, and `git dupe COMMAND -h` or `--help` for `init`, `clone`, `detach`, `hide`, `unhide`, `git`, `help`, `status`, `add`, and `clean` explain those commands and their differences from Git, a screen or less each, and need nothing installed beyond the executable; the texts of `status`, `add`, and `clean` list their tables. `git dupe help` without a command states, in one screen: what a hidden path is and that `git dupe add <path>`, `git dupe hide`, and `.gitdupe` make one; the refusals of G17 and G18 with their alternatives; that plain `git` is not guarded, what `git clean -x`, `git stash -a`, and `git add -f` do to private files, and `git dupe restore .` as the recovery; `git dupe git`; and the supported Git versions. `git dupe help COMMAND` for any other command is `git help COMMAND`, and `-h` on any other command shows Git's usage for it. `git dupe --help` never reaches git-dupe: Git turns it into `git help dupe`, which shows the manual page of F10 when it is installed and Git's help format is `man`. `git dupe --version` prints git-dupe's version.
- **G25.** Requested output goes to standard output and diagnostics to standard error. `warning:` marks something worth knowing after a command that ran: a path public Git does not ignore, a path tracked by both repositories, a released path public Git can see, a file `clone` kept, a count of skipped paths. `fatal:` marks a refusal, `error:` a usage error, `hint:` what git-dupe did or what to do next. Diagnostics name the path, the cause, and the command that fixes it when there is one, never a file's contents. Machine-readable standard output (`--porcelain`, `-z`) contains no git-dupe line and no color.
- **G26.** `status`, `add`, and `clean` read their words against their table: an exact long name, a short letter alone or in a bundle, with its value attached or separate as Git takes it. Read left to right, the first of `-h` or `--help`, which is the command's help (G24), and a dashed word the table does not hold, which is a usage error, exit 129, naming the word and `git dupe git`, decides, and nothing runs in either case; `--` ends the reading, and every word after it is an operand.

## Done when

- In a real project whose `.gitignore` ignores `.env.local`, `.vscode/`, and `build/`, holding a public `docs/design.md`: `git dupe init` succeeds on the project's branch; `git dupe add notes/`, `git dupe add -f .env.local .vscode/`, `git dupe add docs/notes.md`, and a commit leave public `git status` and `git add -A --dry-run` naming none of the private files, `.gitdupe` listing `notes` and `.vscode`, the private commit visible in `git dupe log` and absent from `git log`, the public repository's object count unchanged, and `.git/info/exclude` holding what it held before plus a managed region of exactly the rules for `.gitdupe`, `notes`, `.vscode`, `.env.local`, and `docs/notes.md`; a `git clone` of the project holds neither `.git/dupe`, `.gitdupe`, nor the region.
- Then, with new files `notes/today.md`, `.vscode/launch.json`, `docs/api.md`, and `src/scratch.py`: `git dupe status` lists `notes/today.md` untracked and `.vscode/launch.json` ignored and neither of the other two, and `git status` lists `docs/api.md` and `src/scratch.py` and neither of the first two; with `.env.local` also changed, `git dupe add .` from inside `notes/` stages `notes/today.md` and not `.env.local`, and from the root stages both and nothing under `docs/` or `src/`; after `git dupe add src/scratch.py`, `git status` stops listing it, and after `git dupe rm --cached src/scratch.py` a warning names it and `git status` lists it again; `git dupe add README.md` for a publicly tracked file, and `git dupe add docs/` while `docs/design.md` is publicly tracked, are refused, exit 128, staging and hiding nothing; `git dupe add notes/` after a teammate's publicly tracked `notes/shared.md` has arrived stages the rest and warns of one skipped path, and `git dupe status` does not list `notes/shared.md`; a `!` rule in `.gitignore` re-including `.env.local` makes the next `git dupe status` warn naming that rule's file and line.
- With a private `.env.local` whose staged content differs from its last commit and was saved beforehand, a hidden `notes/` holding a privately tracked `notes/today.md` and an untracked `notes/scratch.md`, a privately tracked `build/local.cfg` inside the ignored `build/` beside a `build/out.js`, and an untracked `scratch.txt`: `git dupe clean -fdx` from the root deletes `build/out.js` and `scratch.txt` and leaves the rest, and, with the same files recreated, `git dupe clean -fdX` deletes `build/out.js` and leaves the rest. Then plain `git clean -fdx` deletes `.env.local`, `notes/`, and `build/`, `git dupe status` shows their files deleted, and `git dupe restore .` from the root brings back `.env.local` with the saved staged content, `notes/today.md`, and `build/local.cfg`.
- On a second clone of the project holding its own differing `.env.local`, `git dupe clone URL` leaves that file unchanged, warns, shows it modified, and brings `.gitdupe`, so that a new `notes/x.md` there is invisible to `git status`; `git dupe pull` and `git dupe push` move commits both ways. `git dupe remote add origin <the project's remote URL>`, `git dupe push <that URL in another scheme> main:leak`, `git dupe push . main:leak` from a subdirectory, `git dupe fetch <the root's absolute path>`, `git dupe push <a linked worktree's path> main:leak`, `git dupe stash -u`, and `git dupe detach` without a remote are each refused, exit 128, naming the alternative, and change neither index, the working tree, `.gitdupe`, the private configuration, the public `.git` beyond its managed region, nor any ref; `git dupe add --pathspec-from-file=x` and `git dupe status --porc` exit 129 naming `git dupe git`, running nothing, and `git dupe git status --porc` is Git's own reading of the abbreviation. `git dupe detach --force` leaves the files on disk, removes `.git/dupe` and the region, and makes `git status` list `notes/` and `.gitdupe`.
- A `git dupe add notes/` and a `git dupe unhide notes/`, each killed at an arbitrary point of its run and then run again: `.gitdupe` and `.git/info/exclude` never held a partial version, and after the second run they hold what an uninterrupted run leaves; a `git dupe init` killed and run again, once any lock file Git names is removed, reports completion and leaves the private repository configured as F2 says.
- In a generated public repository of 100,000 tracked files with hidden paths in three directories, once with 200 privately tracked files and once with 2,000: `git dupe status`, `git dupe add .`, `git dupe commit -m x`, `git dupe switch` to another branch, `git dupe log -1`, and `git dupe clean -n` each run Git a counted number of times that is the same at both sizes, and finish within one second on a warm cache; public `git status` takes the same time as before attachment within measurement noise.
- Every check above passes under every minor Git release the repository lists, from 2.43.0 to the newest 2.x, with the first run obtaining and building them and a second run reusing them; `git dupe help`, `git dupe -h`, `git dupe add -h`, and `git dupe hide -h` show git-dupe's documentation with nothing but the executable installed; with the manual page installed, `man git-dupe` and `git dupe --help` show it; `git dupe log -h` shows Git's; `git dupe --version` prints git-dupe's version.
