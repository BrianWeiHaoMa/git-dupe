# git-dupe — Technical Specification

## Authority

`PRODUCT_SPECIFICATION.md` outranks this document. This document ranks second and outranks every other document, decision, and line of code in this project. Product decisions are not restated here: this document is read together with `PRODUCT_SPECIFICATION.md`, never instead of it. `Approach`, `Foundations`, `Composition`, `State`, `Standing rules`, and `Product decisions settled here` hold unconditionally and are checked by reading the built system. `How the guarantees hold` is true while the system runs, for every run inside the product's operating envelope and inside `Substrate assumptions`; where an entry names a limit, the limit is part of the decision. What this document leaves undecided is open to the code, at its own level. A line found unworkable is not worked around or made to pass by adding an assumption: the conflict and a proposed amendment are reported, and the line is amended before the code changes, as `CONTRIBUTING.md` says; a conflict that reaches a product line is resolved by amending `PRODUCT_SPECIFICATION.md` first. Labels (`S1`, `R1`, `P1`) are permanent and are how the code, the checks, and the other documents cite this document.

## Approach

git-dupe is a launcher for Git. Every command git-dupe passes to Git or changes becomes one Git process for the command itself, or two for an `add` that `Holds/G13, G14` splits, run against the private repository, or against the public one for `clean` (G16), with the repository named explicitly and the environment controlled (G10), and each own command is a short sequence of Git's plumbing; the product is the small amount of work around those processes: reading the words of the guarded commands against fixed tables (G26), refusing the forms G17 and G18 name, writing the pathspecs that confine `status` and `add` and the exclude patterns that make `clean` spare the hidden paths, and, after the process ends, rebuilding the managed region of `.git/info/exclude` from the hidden paths and asking Git what it still exposes (G6). The hidden paths are declared, never derived: `.gitdupe` and the private index are their only sources (F5), read in Git's NUL-separated plumbing forms, and git-dupe matches no pattern and walks no tree (N5, G22). The managed region and `.gitdupe` are each replaced whole by one rename, so that a kill leaves the old file or the new one (G21). Git decides what a pathspec, an ignore rule, or a URL means; git-dupe decides only which literal paths and which words to hand it.

One process, one thread, with a helper thread only to feed a Git child's standard input while its output is read. Git children run one after another, never concurrently. E2 makes one git-dupe per worktree at a time; between the worktrees of one project the only shared state is `.git/info/exclude`, whose replacement is serialized by one advisory lock (`Holds/G28`), and there is no other lock, queue, or state shared between runs.

## Foundations

- **Language and toolchain.** Rust, `rust-toolchain.toml` pinning `channel = "1.98.0"` (F1), edition 2024, the standard library only: process spawning, byte-string paths, rename, canonical paths, exit-status decoding (`ErrorKind::ArgumentListTooLong` for a rejected argument list, `ExitStatusExt::signal` for a signalled child), and the advisory file lock (`File::lock`, S16) are all in `std` on the pinned toolchain. No crate dependency; adding one is an amendment (R7).
- **Executable and packaging.** One Cargo package `git-dupe`, `publish = false`, with one binary target `git-dupe`, installed on `PATH` so that Git runs it for `git dupe …` (S3). The help texts are plain files under `src/` embedded with `include_str!`, and the page's own texts (P2) are plain files beside them; a build script renders them into the manual page `git-dupe.1` in the build output directory (F10, P2). A release is a tar archive holding the binary, the page, and an install note; installation copies the binary into a `PATH` directory and the page into a `man1` directory of the manual path. `cargo install` installs the binary alone.
- **Git.** Every Git command, option, configuration key, environment variable, output format, and pathspec form this document relies on exists at Git 2.43.0 and is unchanged at 2.56.0, apart from the differences `Substrate assumptions` states, checked in the source of both (R6). The checks run under every minor release from 2.43.0 to 2.56.0, built from its official source release under `gits/` at the repository root, which `.gitignore` lists (F4, `Composition/The checks`).
- **Platform.** Linux only (E1, N10). Paths and command-line words are bytes; git-dupe never requires them to be UTF-8.
- **Storage.** The worktree's private repository at `<its Git directory>/dupe` (F2), its managed region of `.git/info/exclude` and a stale region's removal (G27), `.git/info` when it is missing, `.gitdupe`, and the files `clone` writes (G2) are the only things git-dupe writes of its own accord (G5); every temporary file it needs lives inside that private repository. `.git` here and below is the common Git directory, as the product's terms read it.

## Composition

Five parts inside the executable, plus Git and the checks outside it. A part owns what is listed under it exclusively, and other parts reach it only through the operations named. Every workspace path crossing a boundary inside the executable is bytes relative to the workspace root, without a leading or trailing slash, the root itself being the empty path; the runner's location facts and a destination's canonical form (`Guards`) alone are absolute, and a run names its directory as the user's or the root.

### Front

Responsible for the words and the lines. Owns: the dispatch of the first word after `dupe`; alias resolution (G19); the tables of `status`, `add`, and `clean` (G26, P1) and their reading; the reading of the own commands' words (G1, G2, G3, G11, G20); the readings of `stash`'s and the transfer commands' words that `Guards` needs (`Holds/G17`, `Holds/G18`); the help texts (G24); the `level: text` lines (F8, G25); the exit status (F9); and the sequence every command runs.

The sequence: (1) bare `git dupe` prints the general usage line and exits 1; `-h` alone and `--version` are answered; any other dashed first word is the usage error F7 names, exit 129; nothing runs before this. (2) The words of a literal own or changed command are read before anything else — the three tables for `status`, `add`, and `clean` (G26), the own commands' forms for the rest — so that a help request prints the text and exits 0, and a usage error of G26 prints its lines and exits 129, without locating anything; every other usage error of an own or changed command other than `help` — a misuse of an own command's form, a non-literal operand of `status` or `add` — is reported after steps (3) and (5), and a misuse of `help`'s own form at once, because `help` never locates; `help COMMAND` for another word runs `git help COMMAND` in the environment received. A command reached through an alias is read the same way once resolved. (3) The runner locates the workspace; its failure ends the command with Git's message and status (G4), except for a help request or usage error in a command that the first word reaches through an alias, which is resolved as step (4) resolves it, with its lookups made as `Runner` says for a failed locate, and read as step (2) reads a literal one, and except for a help request after a word git-dupe passes through or guards without a table, which `Holds/G24` answers without a repository. (4) A first word that is an own, changed, or guarded command is dispatched as itself, `stage` as `add` (F6). Any other first word is resolved through the private configuration's aliases as `Holds/G19` says: it passes through, dispatches as the command its chain reaches with that expansion's words and leading global options as the command's **prefix**, or is ambiguous, which is refused as `Holds/G19` says after step (5), where it counts as a command that requires an attached workspace (G4). (5) A command that requires an attached workspace is refused in an unattached one, exit 128, naming `git dupe init`. (6) In an attached workspace, for a command G6 covers, the keeper's `start` reads the region as it stands. (7) The handler runs. (8) Every command G6 covers ends with the keeper's `settle`, given that starting region, whatever the handler's outcome, and the front prints settle's warnings. (9) The exit status.

Option reading for the three commands with a table: words are read left to right; a word beginning with `-` is an option unless it follows `--`; a long option matches an exact table name only, with its value after `=` or, where the table says the value is separate, as the next word; a short option matches a table letter, alone or bundled, with its value attached or, where the table says so, as the next word; a `--no-` form is in the table only where listed. The first of `-h`, `--help`, and a dashed word the table does not hold decides (G26): help, or the usage error naming the word and `git dupe git`, exit 129. `--` ends the reading. An own command reads `-h` or `--help` anywhere before `--` as its help request; for `git dupe git`, only as the first word of `WORDS`.

Lines: every line git-dupe writes of its own is one `level: text` line on standard error, uncolored, English, the level one of `fatal`, `error`, `warning`, `hint`, paths as the bytes Git gave or the user typed, except a name holding a newline — a word the user typed, or a rules file outside the workspace, where E4 does not reach — which is written between double quotes as Git quotes such a path, so that the line stays one line (F8, G25). A refusal is one `fatal:` line naming the cause and the command to use instead where the product names one, exit 128. A usage error is one `error:` line naming the fault and, for a word a table does not hold, `git dupe git`, then the command's own usage line, exit 129. The wording of each line is the implementation's, within what its guarantee says it names. Requested output of git-dupe's own — help texts, usage on bare `git dupe`, the version line `git-dupe version <package version>` — goes to standard output. A Git child killed by a signal ends git-dupe with 128 plus the signal number.

### Runner

Responsible for locating the workspace and running Git; nothing else starts a process (R1). Owns: the workspace facts and the two environments.

The facts come from one public `git rev-parse --path-format=absolute --git-dir --git-common-dir --show-toplevel --show-prefix` in the environment git-dupe received and from its directory, so that `-C`, `--git-dir`, and `--work-tree` before `dupe` name the public repository as Git read them (G19): the root, the user's prefix below it, the public Git directory, the common Git directory, and from them the private Git directory `<Git directory>/dupe` (F2), **attached**, which is that path being a directory, and **linked**, which is the Git directory and the common Git directory differing, the worktree's **name** then being the last component of the Git directory (E9, S17). For `init` and `clone` the run also carries `--show-superproject-working-tree`, whose non-empty answer marks a submodule checkout (G4). A failing `rev-parse` that printed nothing is "outside any repository"; one that printed the Git directory and the common Git directory before failing is a bare repository's own directory or a directory inside a Git directory. Git's own message and status end the command, except as `Front` step (3) says, whose runs are made as a private run with `GIT_DIR` set to `<Git directory>/dupe` and `GIT_WORK_TREE` removed when the failing `rev-parse` printed them, and in the environment received when it printed nothing.

A **public run** inherits git-dupe's environment, with a relative `GIT_DIR` or `GIT_WORK_TREE` made absolute against the user's directory, `GIT_INDEX_FILE` removed from every `ls-files` that asks which paths are publicly tracked, so that it reads the public index and not the temporary index of a hook (S9), except the listing `clean` asks before it runs, which reads the index its `clean` reads, and `GIT_LITERAL_PATHSPECS`, `GIT_GLOB_PATHSPECS`, `GIT_NOGLOB_PATHSPECS`, and `GIT_ICASE_PATHSPECS` removed from every run whose pathspecs or paths git-dupe wrote itself. A **private run** sets `GIT_DIR` to the private Git directory and `GIT_WORK_TREE` to the root, both absolute, removes `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, and `GIT_REFERENCE_BACKEND`, removes the four pathspec variables on the same condition, and passes everything else through, including what Git set for its global options (G10, G19, S3). A run of git-dupe's own `git config`, public or private, also has `GIT_CONFIG` removed, because Git reads that variable only in `git config`, as if `--file` named it. Every run whose command word is the user's carries `-c help.autocorrect=0` before that word, which outranks the configuration and a `-c` before `dupe` (G19, S10). A run names its directory (the user's unless stated), the command's prefix from alias resolution, its arguments as bytes, whether standard output is inherited or captured, and the bytes fed to standard input when it feeds any; standard input is inherited when nothing is fed; standard error is inherited, except that a run whose failure is an answer rather than an error — the locate `rev-parse` and the keeper's `cat-file` — captures it, and the front prints the locate run's when that failure ends the command. It returns Git's exit code or signal and the captured bytes. A spawn failing with `E2BIG` is a distinct outcome (G23).

### Keeper

Responsible for the hidden paths, the managed region, `.gitdupe`, and what public Git says about each hidden path. Owns: reading and writing `.gitdupe`; the managed region, between the markers F3 gives this worktree, and its rule form (F3); the reading of the other worktrees' regions and the dropping of a stale one (G27); the lock under which `.git/info/exclude` is replaced (`Holds/G28`); the derivation of the **region paths**, the hidden paths not below another hidden path; the exposure question; the warnings of F5, G6, G8, G9, and G27.

Operations. **Hidden paths** reads `.gitdupe` — the file at the root, through a symbolic link, or, when nothing stands at that path, its staged version from one private `git cat-file blob :.gitdupe`, whose failure means no listed path — one path per line as F5 reads it, dropping a leading and a trailing `/`, skipping an empty line, and setting aside, with its line, a line that names the root or a path outside it; when something stands at `.gitdupe` that cannot be read as a file, the listed paths are none and the entry is set aside the same way; then one private `git ls-files -z --full-name` from the root for the privately tracked files; and returns the hidden paths, the region paths in byte order, the set-aside lines, and the privately tracked files. **Public listing** takes a list of query paths — the region paths, the released paths, and the foreign paths for settle, the paths `Remove` asks about for `Remove`, the scope for `status` and `add`, the operands for `hide`, the ancestors of the region paths that hold a `.git` entry and, under `-X` without `-d` or a pathspec, the region paths at which a directory stands, for `clean`, read from the index `clean` reads, and `.gitdupe` beside any of them — and the privately tracked files, asks one public `git ls-files -z --full-name` under the query paths, each written `:(top,literal)<path>`, and returns the publicly tracked paths under them, split into those equal to a privately tracked file, **tracked by both** (G8), and the rest, the **skipped set** that `status` leaves out and `add` skips. **Start** reads the region as the command begins, its rules read back into paths, a rule that does not parse ignored, and returns them for the front to hold. **Settle** takes that starting region, recomputes the hidden paths, replaces the region with one rule per region path, takes the public listing under the region paths, the released paths, and the foreign paths, asks one public `git check-ignore --no-index -v -n -z --stdin` from the root, each path written `./<path>`, about every hidden path, every released path — in the starting region, neither among the new hidden paths nor below one, and present by `lstat` — and every **foreign path**: a path of another worktree's region, as the file stood when it was replaced, whose worktree holds a private repository, that is neither equal to nor below one of this worktree's hidden paths, and that is present under this root by `lstat`; except a path with a symbolic link among its ancestors by `lstat`, which Git refuses to answer for and which, as a hidden or released path, is named instead in a `warning:` as lying beyond a symbolic link, where public Git does not look (G6), and as a foreign path is left unasked and unnamed; and returns the warnings. `check-ignore` exiting 1 means no path matched and is not a failure; any other failure of it is one `warning:` that exposure could not be checked, the command's status unchanged. Settle's G27 warnings are one `warning:` per foreign path that the run reports ignored and that the public listing does not name as publicly tracked itself, naming the path and the worktree, `the main worktree` or `worktree <name>`; where settle leaves the region as it is, none is produced (G27). A listing that settle needs and cannot take — the private one, as a killed `init` leaves the repository until it is run again (G6, G21), the public one, or a run that cannot start — leaves the region as it is and is one `warning:`, the private listing's naming `git dupe init`, the command's status unchanged; the same failure inside a handler ends the command with Git's message and status. **Remove** takes the hidden paths as they stood, deletes the region with its markers by the same replacement, asks the same `check-ignore` about those still present and the public listing under them, and returns the warnings naming the ones public Git does not ignore and, among the ones the run reports ignored and the public listing does not name, those equal to or below a path of another worktree's region as the file stood, each naming that worktree (G3), for `detach`; a failed listing is a `warning:` as a failed `check-ignore` is. **Rule** gives the region rule of a path, for `clean`'s patterns. **Hide** and **unhide** take cleaned root-relative paths after their caller has decided the refusals of F5 and G11 over a public listing, rewrite `.gitdupe`, and stage it with one private `git add -f -- :(top,literal).gitdupe`; hide appends one line per path not already listed or below a listed path, unhide removes each line whose cleaned path equals a given path, both keep every other line byte for byte, rewrite the file only when a line changes, stage it whenever it exists on disk as a file, so that a retry after a kill stages what the killed run wrote, and return the paths they changed.

A region rule is `/`, then the path with `\` before each `\`, `*`, `?`, `[`, `#`, `!`, and space, and each carriage-return byte written as a bracket expression holding that byte; it has no trailing slash, so that it matches exactly that path whether a file, a directory, or nothing stands there (F3, S5). Rules stand in byte order of their paths. The markers are F3's, each matched as a whole line: `# BEGIN git-dupe` and `# END git-dupe` for the main worktree, `# BEGIN git-dupe worktree <name>` and `# END git-dupe worktree <name>` for the linked worktree named `<name>`; the managed region runs from this worktree's first begin marker to the first end marker after it, or to the end of the file when there is none; every other git-dupe marker pair bounds another worktree's region, whose rules are read back into paths as `Start` reads them. The region is present, with its markers, whenever the workspace is attached, except where a symbolic link at `.git/info` or a dangling one at `.git/info/exclude` keeps it from being written (G6) and after a kill before the first settle of `init` or `clone` or between the two steps of `detach` (G21); it is absent otherwise. `.git/info/exclude` is replaced whole, under the lock (`Holds/G28`): the file is read, the user's text and the other regions are copied byte for byte around this worktree's new region — except a region whose worktree holds no private repository, its private Git directory not a directory by `lstat`, which is left out (G27) — the new content is written to a fresh file inside the private repository, given the original's permissions, and renamed over `.git/info/exclude`, and the lock is released; a composition equal to the file as read makes no write. `.git/info` is created when absent, a directory that another worktree's command made first counting as created; a symbolic link at `.git/info/exclude` that resolves is read through and replaced by a regular file, its target untouched and a `warning:` naming the replacement. Before writing, the keeper checks by `lstat` for a symbolic link at `.git/info` and a dangling one at `.git/info/exclude`, and then leaves both untouched and returns G6's warning that the region cannot be maintained there. `.gitdupe` is written the same way, without the lock: a fresh file inside the private repository, the existing file's permissions when one exists, renamed onto `<root>/.gitdupe`; a failed rename — one across filesystems, where a linked worktree lies outside E1, included — fails the command that asked, exit 128, naming the cause (F5) and changing nothing else, and a failed staging run after the rename fails it with Git's status, the file written.

### Attachment

Responsible for `init`, `clone`, and `detach`. Owns: creation and removal of the worktree's private repository; the keys F2 and G1 require in its configuration, `core.worktree` among them as the **relative work tree**, the lexical relative path from the private Git directory to the root over their canonical forms, `../..` in the main worktree; the write step of G2. It uses the runner for every Git step, the keeper to remove the region and name what `detach` exposes, and `Guards` to compare `clone`'s URL.

### Guards

Responsible for the commands whose Git form git-dupe changes or refuses — `status`, `add`, `clean`, the untracked forms of `stash`, and the destinations of `push`, `pull`, `fetch`, `remote`, and `clone` — and for `hide` and `unhide`, which share `add`'s operand resolution and refusals. Owns: the resolution of an operand to a root-relative path (G11, G13); **pathspec**, the one constructor of every pathspec git-dupe writes, in the magic form `:(top,literal)<path>`, `:(top,literal,exclude)<path>`, or, for `status` alone, `:(top,glob,exclude)<exact>`, `<exact>` being the path with `\` before each `\`, `*`, `?`, and `[`, and its last byte written as `[\<byte>\<newline>]`, a bracket expression matching that byte or a newline, so that `wildmatch` matches that path and nothing below it, and the pattern's raw bytes, which Git compares with each path first, hold a newline and so name no path inside the workspace (E4, S4), which the keeper calls for its listings and its staging; the `-e` patterns of `clean`; the canonical form of a destination and the public-place comparison (G18); the refusals of F5, G11, G13, G14, G16, G17, and G18, each decided from the keeper's public listing before any write. An operand is cleaned lexically: joined to the user's prefix unless absolute or beginning with `:/`, then `.` components, `..` components with their parent, repeated and trailing slashes removed; an absolute operand is cleaned and then made relative to the root when it lies below it; one that resolves to the root or outside it is what G11 and G13 say (R9). No user pathspec reaches Git from `status`, `add`, `hide`, or `unhide`: every pathspec of their runs is git-dupe's, which is why those runs drop the pathspec variables and the pathspec options of a prefix (`Runner`).

### Git

The dependency outside the executable, found as `git` on `PATH` (E5). What crosses: an argument vector of bytes, an environment, a directory, inherited or captured streams, an exit status; what git-dupe reads back is only the machine forms R5 names. Git's own standard output and standard error reach the user untouched for every command git-dupe passes to it.

### The checks

The one integration test target of the package, `tests/scenarios/`, plus the unit checks beside the code. It owns the list of Git releases the repository checks — every minor release from 2.43.0 through 2.56.0, raised as new ones appear (F4) — and, for each, a directory `gits/git-<version>/` holding that release built from `git-<version>.tar.xz` at `https://mirrors.edge.kernel.org/pub/software/scm/git/`, obtained and built by the harness itself when the directory is absent — the tarball downloaded, its SHA-256 checked against the entry in `sha256sums.asc` from the same directory, and `make prefix=<that directory> RUNTIME_PREFIX=YesPlease NO_GETTEXT=1 NO_TCLTK=1 NO_PERL=1 NO_PYTHON=1 NO_CURL=1 NO_EXPAT=1 NO_OPENSSL=1 NO_RUST=1 install` run in the extracted source (S14) — and reused when present; `gits/` is in `.gitignore` and never in a commit. Every scenario is generated once per listed release and runs with that release's `bin` and the built `git-dupe` at the front of `PATH`, so that `git dupe …` is the whole route; the Git on `PATH` outside `gits/` is not a target. A scenario asserts through `git dupe` on git-dupe's own lines, exit statuses, and effects — the two indexes, the region, `.gitdupe`, the files on disk, the refs — and never on the text of a Git message or with a per-release expected value. Every scenario runs with `HOME` and `GIT_CONFIG_NOSYSTEM=1` isolating it from the machine's configuration, `GIT_SSH_COMMAND=false` and only local remotes, so that no check touches the network after the releases are obtained. The scenarios of a linked worktree — of an ordinary repository and of a bare one, two worktrees' commands started at the same moment, `git worktree move`, `remove`, and `prune` — run under every listed release like the rest, their layouts made by the harness through `git worktree` alone. The harness's environment variable `GIT_DUPE_CHECK_RELEASES`, a comma-separated subset of the list, narrows a focused run; the delivery check is the full list. The manual-page scenario installs the generated page into a temporary manual path and asks `man git-dupe` and `git dupe --help` under `MANPATH` (G24, F10), which needs `man` on the checking machine. Obtaining the releases needs `curl`, `tar` with `xz`, a C compiler, `make`, and the zlib and C library headers; the built programs link the machine's zlib and C library dynamically.

## State

The records of truth are Git's — the worktree's private repository and the public repository under `.git`, each with its index, refs, objects, reflog, configuration, and in-progress state — and `.gitdupe`, the developer's declared list, itself a privately tracked file (F5). git-dupe keeps no other record (N4, N6). The managed region is derived from `.gitdupe` and the private index and rebuilt whole by every command G6 covers; a stale or missing region is never repaired in place, only recomputed. The user's part of `.git/info/exclude` is the user's record and is copied through unchanged, and so is every other worktree's region, except one whose worktree holds no private repository, which is dropped (G27). Between the worktrees of one project, `.git/info/exclude` is the one shared record, and its replacement is the one operation under the lock (`Holds/G28`); each worktree's private repository and `.gitdupe` are its own.

Change points:

- **A command Git runs** takes effect when Git says it does; git-dupe adds nothing before Git's change, other than the `.gitdupe` write of a hiding `add`, and, afterward, only the region replacement and the warnings. A kill during Git leaves what Git leaves; a kill before the replacement leaves the previous region; the rename is the single point at which the new region exists, and after it only the warnings can be missing (G21).
- **`.gitdupe`** changes at its rename; the staging that follows is a separate Git step, and a kill between the two leaves a written, unstaged file that a rerun of the same `hide` or `unhide`, any later `hide` or `unhide`, or the developer's own `git dupe add .gitdupe` stages; a rerun of a hiding `add` finds its directory hidden and stages the file only through those. The hidden paths read the file on disk first, so the region follows the write at the next settle whatever the staging.
- **Region replacement** is the rename under `Keeper`, inside the lock. A failed write or rename, and a lock that cannot be taken, is a `warning:` naming the cause and that private files may be visible to public Git; the exit status stays the command's (F9). A kill while the lock is held releases it with the process's descriptors (S16) and leaves the file old or new (S1); a command waiting for it in another worktree then proceeds. In `detach`, whose deletion of the region is the first of its two steps, a failed write or rename, or a lock that cannot be taken, refuses, 128, naming the cause, with the region and the private repository as they were (G3).
- **`init`** takes effect in Git's `init`; the keys follow in separate `git config` runs; a kill between steps leaves an attached workspace missing keys or its region, which the next `init` completes (G1); a lock file Git left behind stops it with Git's message until it is removed (G21).
- **`clone`** is a sequence of Git steps after its refusals, each leaving the workspace attached with what was done (G2, `Holds/G2`).
- **`detach`** removes the region first and the private repository second, so that a kill after the first step leaves an attached workspace that `detach --force` completes, and a kill during the second leaves a directory the same command removes (G3, G21).
- **Acknowledgement.** A command that ended without a `fatal:` line and with status 0 did everything it says. An interrupted caller reruns the command: every command G6 covers is idempotent in its region work, `init` and `detach --force` are idempotent as G1 and G21 say, and Git's commands keep Git's retry rules.

## How the guarantees hold

Guarantees not listed need no entry: G7 falls out of the rule form, because a rule without a trailing slash excludes a directory at its path with everything below it, and out of recomputing the region on every command; G15 is the private run of `add` once G13 and G14 have passed; G21 is `State`; G25 holds because the front writes to standard error only `level: text` lines and the usage line after an `error:` line, and to standard output only its own help texts, the usage of bare `git dupe`, and its version.

### G1. `init`

The one shared record is `.git/info/exclude` (`State`). ## Substrate assumptions

The arrangements above hold inside the product's operating envelope (E1–E8) and the assumptions below; outside either nothing is promised. Each is stated as its primary source conditions it, for Git at 2.43.0 and unchanged at 2.56.0 unless it says otherwise.

- **S1.** On the local filesystem of E1, `rename(2)` of a file onto an existing path in the same filesystem replaces the destination atomically: another process sees the old file or the new, never neither, and a process killed before the call leaves the destination unchanged. A rename onto a symbolic link replaces the link itself. Nothing here assumes the new content survives power loss.
- **S2.** `execve(2)` fails with `E2BIG` and runs nothing when the argument vector and environment exceed the kernel's limit; within it the program receives every argument whole. A builtin or an external command found this way is run before an alias of the same name is consulted, except as S11 says.

- **S16.** On Linux, `flock(2)` places an advisory lock associated with the open file description: an exclusive lock makes every other request for an exclusive or shared lock on the same file wait, from another process or from another descriptor of the same process alike, until it is released explicitly or every descriptor of that description is closed, which the process's exit, a kill included, does for the descriptors it alone holds, while a descriptor a child inherited keeps the lock held; a directory opened read-only can be locked. ## Standing rules

R1 and R4 stand with their guarantees above. In addition:

- **R2.** No public run other than the `clean` of G16 is a command that writes: not `add`, `update-index`, `write-tree`, `rm`, `reset`, `checkout-index`, `worktree` other than `list`, or `config` without `--get`, `--get-regexp`, or `--list`. The public index is read only through `ls-files`.
- **R3.** Every command that ends in an attached workspace, other than `help`, `-h`, `--version`, a usage error, and `detach`, ends with the keeper's `settle`, on success and on failure alike, `init` and `clone` included. A command or refusal added later calls it too.
- **R5.** git-dupe never parses a Git message meant for humans and never sets `LC_ALL` or `LANG` for a child; every answer it reads from Git is a `-z` listing, a `rev-parse` line, a `check-ignore -v -n -z` record, a `config -z` record, a `--list-cmds` name line, a `for-each-ref --format` line, an `ls-remote --symref` line, a `symbolic-ref` line, a `--porcelain -z` record, a `rev-list` or `stash list --format=%H` hash line, or the bytes of a blob from `cat-file`.
- **R6.** Nothing git-dupe gives Git or reads from it — a command, an option, a configuration key, an environment variable, an output format, a pathspec form — is one that Git 2.43.0 lacks or that a later release through the newest listed changes, apart from a difference `Substrate assumptions` states, and a table (P1) holds only what F4 allows; a doubt is settled in the source of both releases before the code relies on it, and the fact is added to `Substrate assumptions`.
- **R7.** A new own command, option, environment variable, configuration key, file, or crate dependency is an amendment to `PRODUCT_SPECIFICATION.md` first (F6, F7, N6); the help text and the manual page change together with any behavior they describe, in the same change.
- **R8.** Of git-dupe's own accord nothing is written outside the worktree's private repository, the region rename, `.git/info` when it is missing, `.gitdupe`, and the files `clone` writes as G2 describes, and nothing is deleted except the private repository by `detach` and a stale region by the rename (G27); a command passed to Git writes and deletes where the developer's words tell Git to, and the user's own `clean` deletes what G16 says (G3, G5, G16).
- **R9.** git-dupe never matches a pathspec, expands a glob, or evaluates an ignore rule itself; the lexical cleaning of an operand, the relative work tree, the canonical form of a destination, the region rule form and its reading back, and the ancestor and membership tests over Git's listings and the other regions' paths are the only comparisons it performs on paths and destinations (N5).
- **R10.** `.git/info/exclude` is read for replacement, composed, written, and renamed only at the keeper's one replacement site, under the lock of `Holds/G28`, taken once per command on the common Git directory and held across no Git run; no other code path opens the file for writing or takes the lock.

## Product decisions settled here

- **P1.** From L1, the tables, each option with the value form Git gives it in every listed release. `status`: `-v`/`--verbose`, `-s`/`--short`, `-b`/`--branch`, `--show-stash`, `--ahead-behind` and `--no-ahead-behind`, `--porcelain[=<version>]`, `--long`, `-z`/`--null`, `-u[<mode>]`/`--untracked-files[=<mode>]`, `--ignored[=<mode>]`, `--ignore-submodules[=<when>]`, `--column[=<options>]` and `--no-column`, `--renames` and `--no-renames`, `-M[<n>]`/`--find-renames[=<n>]`; every value here is optional and attached. `add`: `-n`/`--dry-run`, `-v`/`--verbose`, `-p`/`--patch`, `-e`/`--edit`, `-f`/`--force`, `-u`/`--update`, `--renormalize`, `-N`/`--intent-to-add`, `-A`/`--all` and `--no-all`, `--ignore-removal` and `--no-ignore-removal`, `--refresh`, `--ignore-errors`, `--ignore-missing`, `--sparse`, `--chmod=(+|-)x` with its value attached or as the next word. `clean`: `-q`/`--quiet`, `-n`/`--dry-run`, `-f`/`--force`, `-i`/`--interactive`, `-d`, `-x`, `-X`, `-e <pattern>`/`--exclude=<pattern>` with its value attached or as the next word. A value taken as the next word is whatever word follows, `--` included, as Git takes it. Every other spelling — `-i` and `--pathspec-from-file` for `add` (N11), an abbreviation, `--end-of-options`, and every option a later release adds — is a word the table does not hold (G26). Each command's help text lists its table, and the manual page repeats it (G24).
- **P2.** From L3, the manual page. A build script in the package renders `git-dupe.1`, in man macros, from the same embedded help texts `git dupe help` prints — the general text as the description, each command's text as its own section, the tables included — so that the two cannot drift, and from the page's own texts: plain files beside the help texts that `git dupe help` never prints, holding what F10 lets the page say beyond them — the quick start, the examples, the explanations — each rendered as its own section. Prose is rendered in fill mode, so that `man` fits it to the terminal's width; a usage line, a command list, an option table, and an example command keep their lines as written; and the page as `man` shows it at 80 columns has no line wider than 80. The script writes the page into the build output directory. A release archive holds the binary, the page, and the install note; installing the page is copying it into a `man1` directory on the manual path, which is what makes `git dupe --help` and `man git-dupe` show it (G24); `git dupe help` needs nothing installed beyond the executable, because the texts are embedded.
